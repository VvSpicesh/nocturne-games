# Phase 26：主体优先、拼豆原色锁定与色数软限制

更新：2026-11-09。本说明记录保色和色数软限制，取代之前“超过 16 色必须停留草稿”的规则。
当前三档已改为区域级换色，最新统计、换色率和 193 项测试结果见 [区域说明](./README-REGIONS.md)；下方旧点击/换色率表仅作颜色阶段历史记录。
图片仅在本地处理；没有执行 commit、push、部署、真实网络或浏览器端到端测试。

## 主体先于颜色

图片模式默认自动识别，支持强制拼豆原色锁定及普通图片。
锁定模式先识别规则豆阵和有效位置，对豆格做八邻接连通域分析，默认只保留最大主体，再统计中心色及建立调色板。
背景、横幅、奖励和孤立装饰只要不属于所选豆阵主体，就不进入 target、换色率、颜色计数或引擎点击。
豆间微小缝隙不会变成空格；真实内部空洞保持 inactive，导出为 '.'。

“手动框选主体”会在裁剪窗口进入拖框模式。松开后先限定原图取景范围，再识别框内最大主体。
可用“清除主体框选”返回原取景；缩放、移动仍限制在选框内。框选只保存坐标，不改动源图片。
裁剪、重新识别或人工修正会废弃旧解法；框选期间旧颜色按钮不会重新验证旧 target。

## 16 色是推荐值

| 当前主体色数 | 默认行为 | 明确可用的动作 |
| --- | --- | --- |
| ≤16 | 保留当前色数，正常生成 | 裁剪、编辑 |
| 17–24 | 提示超过推荐值，直接进入真实引擎验证 | 保留、按色系合并到 16 色、返回框选 |
| >24 | target 正常预览，等待选择策略 | 明确保留当前色数尝试验证、按色系合并、返回框选 |

高色数保留不会重新量化 target，也不会把未经验证的结果标成可玩。
程序有 63 个候选色的技术容量，与现有游戏存档保留空格符号后的编码容量一致；
这不是推荐色数，超过该容量会提示进一步框选或调整中心聚类容差。

页面分别显示目标图生成状态、检测色数、当前色数、推荐色数、当前策略以及三档验证状态。
超过推荐值不等于生成失败；超过 24 色时提供明确按钮，不再只留一段说明。

## 按色系合并到 16 色

先按红、橙、黄、绿、青、蓝、紫、粉和深/浅中性色分组，只在兼容色系内挑选合并对。
色差、有效豆数量及颜色支持率用于决定合并顺序，高光和阴影优先并入同色系的主要代表。
代表色考虑频率、饱和度与亮度，黑色轮廓有保护；黄/橙、粉/紫、蓝/青不直接混成一色。
合并只选择原调色板中实际存在的颜色，不求异色 RGB 平均，不增加灰色过渡色。
原始中心采样调色板保留供对照；手动改色和单颗豆色修正仍然可用。

## 保色与三档玩法

拼豆模式中心区域稳健采样，避开中心小孔、高光、外围边框和阴影。
默认不应用饱和度或亮度增强。普通图片仍提供原色优先、平衡、柔和模式，
默认饱和度 +8%、对比度 +4%，且先提取主体再量化。
12 主色合成样本的普通模式平均 ΔE76 为 2.34、95 分位 5.33，保留 12/12 主色类别。
这些保色指标不等于人工视觉验收。

三档使用完全相同的 target、尺寸、mask 和调色板；只改变 initialRows 与玩法乱序结构。
合并动作只在生成三档前改变一次 target，难度模块不重新量化。
生成及导出/回读都用当前 TurnBeansEngine 点击序列和游戏已有 autoFillMatchingEmpty 回放。
必须最终棋盘完全正确、三盘清空，且每次最多取 10、每盘最多 20，才能标记可玩。

JSON 保持 schemaVersion:1，扩展单字符调色板为 A–Z、a–z、0–9、-，'.' 只代表 inactive。
旧 A–P 行编码不变，旧六关不变；行数、行宽、符号、颜色守恒和统计仍严格校验。
每张文档只存一份 target.rows；新增可选 source.colorStrategy 和 source.subjectRect 元数据。
关卡库及发布接口使用同一校验器，客户端 verified 字段不能跳过引擎回放。
扩展编码的关卡需要配套更新后的读取器；未配置的 GitHub 授权/发布后端保持禁用。
